#### Feature #28: Session invalidated on password change ✅
**Status:** PASSING
**Implementation:**
- Added `passwordChangedAt` timestamp field to User entity
- JWT tokens include `pwdChangedAt` claim with epoch milliseconds
- Custom JWT validator in SecurityJwtConfiguration checks timestamp on every request
- If user's passwordChangedAt > token's pwdChangedAt → token rejected with JwtException
- UserService.changePassword() sets passwordChangedAt to Instant.now()
- Liquibase migration `20260223140000_add_password_changed_at_to_user.xml` adds column

**How It Works:**
1. User logs in → JWT includes `pwdChangedAt: 1234567890`
2. User changes password → DB updated with `passwordChangedAt: 1234567999`
3. Old JWT validation checks: 1234567999 > 1234567890 → reject (HTTP 401)
4. User must login again → new JWT with updated timestamp

**Code Evidence:**
```java
// SecurityJwtConfiguration.java - Custom validation
if (user.getPasswordChangedAt() != null &&
    user.getPasswordChangedAt().isAfter(tokenPasswordChangedAt)) {
    LOG.warn("JWT rejected: password changed after token was issued");
    throw new JwtException("Token invalidated due to password change");
}
```

- ✅ Code compiles successfully
- ✅ Spotless style check passes
- ✅ Liquibase migration registered in master.xml

- ✅ Real database integration via UserRepository
